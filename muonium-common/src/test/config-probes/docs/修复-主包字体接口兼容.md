# 主包字体接口兼容修复

日期：2026-11-24。输入：错误报告-11-24-2026_12.08.56.zip，崩溃记录时间 12:08:49，MC 26.3 / Fabric / MuoniumPlayer 2.6.1 / Skija Preview 0.1.0-dev。

## 原因与修复

报告的首个致命异常为 NoSuchMethodError，符号是 CFontRenderer.drawPlainTextWithPaintOn(Canvas,String,float,float,Paint):boolean，发生于 HostTextRenderer.Run.draw 绘制设置中心侧栏文字。验收包以本地主项目开发 classpath 编译时能找到这个方法，报告对应的实际主包没有该声明。仅用本地 classes 验证遗漏了发布二进制差异。

修改仅位于独立验收工程，主项目源码和原附属仓保持原状。普通填充改用已经核对的公开 drawGlyphsOn(Canvas,String,double,double,int,int,float,Shader):boolean；描边使用对应目标已核对的 drawGlyphsOutlineOn(Canvas,String,double,double,int,float):boolean。保留原 Canvas、基线换算、字宽、回退字体和资源拥有者。没有捕获并吞掉 LinkageError，也没有通过禁用文字或空实现绕过崩溃。

注意：主包版本号相同不代表字节相同。该修复不会宣称任意历史 2.6.1 JAR 均有相同接口。用户报告中的主包、当前实际安装主包及工作区发布目录分别按字节/真实声明核对；最终 26.3 Fabric 验收包额外绑定实际主包 SHA-256。

## 新增验证方式

build.ps1 新增 HostJar 参数，仅允许单一版本线和加载器，编译 classpath 使用指定主包而不使用本地 main.output。产物 skija-config-build.json 写入 hostJarSha256，便于验收人确认编译对象。

字体 run.ps1 同样新增 HostJar，运行时排除本地宿主 classes/resources，将真实主包放在前面。UiOnly 只执行设置页实际文字路径；默认仍执行完整字体、HUD 样式、回退、缓存、线程及资源生命周期检查。

## 已观察验证

- 修复前共享文字实现与不含新 paint 方法的发布主包组合，实际复现了同一 NoSuchMethodError 和 Run.draw 调用点。
- 同一缺少新 paint 方法的主包下，修复后的 UI 绘制回归通过。该检查只证明 UI 填充路径，不将其扩大为这个旧包的全部 HUD 描边兼容。
- 真实安装主包下，字体契约 26 项、完整 CPU/Skija 字体检查 157 项通过。其中新增 36 组逐像素比较，覆盖中文、混排、3 种字号和 4 种透明度，验证基线/像素/alpha 保持一致。
- Java 17 中立回归通过。用户随后将本次构建范围收窄为 26.3 Fabric，其余批量构建已中止；本轮最终结论只覆盖 26.3 Fabric。该目标使用实际安装主包重新编译，结果见 build/fix-installed-host-build.log。其他版本/加载器不作为本次修复的最终构建或运行通过结论。
- 本轮没有启动游戏、自动替换游戏 mods 或修改主项目源码。游戏打开、切屏和 HUD 效果仍交人工验收。

## 人工使用

用本轮 dist 下对应的 Skija 验收包替换旧 Skija 验收包，主项目仍使用匹配的主包；不要同时安装两份同 id 的 Skija Preview。打开 H 后先确认文字正常显示，再验收主题、HUD 与输入。崩溃日志中的 legacy_default 字体警告与本次致命 NoSuchMethodError 是不同问题，本次不改写字节保真的原资产来掩盖该警告。
