`C:\MUSIC\muonium-common\src\main\java\com\muoniumplayer\core\screens\ncm\ListenTogetherOverlay.java`

### 删掉的旧骨架（从 NcmSheet 继承）

- `private boolean closing` → NcmSheet.protected `closing`
- `private final SheetClock clock = new SheetClock()` → NcmSheet 的 `clock`（cascade）
- `private double presentation` → NcmSheet.protected `presentation`
- `private double dialogHeight` → NcmSheet 的 `sheetHeight`（内部由 sheet() 推）
- `isDismissing()` / `shouldClose()` / `dispose()` 整段删掉，全部走父类
- `private Panel createDialog(...)` 整段删掉，改成两处 `sheet(...)` 调用
- 自写的 `mix(int, int, double)` 删掉（继承 NcmSheet 的 public static，否则权限问题编译报错）

### 翻页语义

  perFrame 挪到 `onRender` 覆写里，靠 NcmSheet 的 onRender 先把两条时钟推进完再读它

### 教训（备忘）

- 迁移 NCMPanel→NcmSheet 第一坑：旧的私有 `mix()` 静态方法会和 NcmSheet 的
  `public static int mix(int, int, double)` 撞名，权限更严会被编译器当覆盖而拒绝
  （"正在尝试分配更低的访问权限; 以前为public"）。直接删自己的版本让继承生效即可。
- 每次翻页要 `beginPage()`；仅首次进入（onInit 里直接调）也照样 `beginPage()`，
  因为清的是空 list 没成本，但这样省去「是不是首次」的分叉。
- `NcmSheet#back(Runnable)` 必须包一层 Runnable 再 `.run()`，因为它返回的就是 Runnable，
  单纯 `back(this::showOverview)` 不会触发翻页方向标记。
