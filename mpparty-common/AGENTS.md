# mpparty-common 一起听共享层规范

> 继承根 `AGENTS.md`，语言/依赖/布局底线参照 `muonium-common/AGENTS.md`。核对：2026-11-11。

## 定位与边界

本目录挂载到七树的十四个加载器目标，不独立构建。包含服务端房间客户端、直连、局域网与播放器集成，不只是一条“服务端没装 mod 就空转”的路径。

| 层 | 边界 |
| --- | --- |
| 协议、房间视图、控制状态机 | 保持版本/加载器中立；协议行为须与服务端一致 |
| `MpHost` 与宿主路由 | 封装连接、发送及客户端宿主操作；loader 通道注册/载荷包装留各树外壳/版本层 |
| `MpPlayback` 等播放器桥 | 遵守播放控制拦截与房间权限，不绕过状态机直接驱动播放器 |
| `lan/` 集成服务器适配 | 现有 `LanMpPlatform` 使用 MC 服务器类型，是已经存在的窄边界；不能据此把 MC/loader 注册扩散到协议层 |
| `mpserver-core/` | 另一个目录的只读同步镜像；不在客户端仓手改房间引擎或协议实现 |

本目录同样禁止加载器符号。**并非整个目录绝对禁止 MC 类型**：旧 README 的这一描述已不符合局域网实现；新增 MC 触点应优先放宿主/compat，确需共享适配时先证明七树 API 一致并记录原因。

## 变更要求

- 遵守根规范「API 与版本事实」：网络注册、payload/codec、生命周期事件及回调线程按「MC 精确版本 × 加载器 × 实际依赖版本」分别核实；不因协议相同就推断宿主网络 API 相同，禁止编造方法或照搬相邻版本。
- 统一宿主接口只约束业务语义，不能证明底层实现可复用。查不到准确声明或运行依据时明确“未确认”，不得凭记忆补替代 API 或静默吞异常伪造支持。

- 网络通道、玩家身份/聊天/调度差异通过宿主桥处理，不向协议层泄漏某版 payload/event API。
- `MpProto` 的分帧、编码、字段及容错行为是线协议；改前检查服务端和旧客户端兼容性，不仅验证 JSON 看起来相同。
- 播放、暂停、跳转、纠偏等走 `MpPartyClient`/现有路由的统一权限路径；避免本地 UI、直连与服务端房间同时接管播放。
- 明确状态归属和线程；网络回调不直接碰 GUI/音频端口，切换房间、断连及退出时清理监听和过期任务。
- UI 沿用共享组件体系；宿主 API 差异拆小型桥，不把整个房间面板复制到各树。
- Java/Kotlin 仍受最老车道限制；不要因网络库在 26.3 可用就直接增加共享依赖。

## 验收

- 共用代码改动跑七树 `:fabric:test`；生产代码或依赖改动还需七树双加载器构建。
- 改通道/注册时运行相关树的两个加载器客户端。
- 按实际受影响模式补测服务端房间、直连或 LAN：创建/加入、播放权限、暂停/跳转、重连/退出、过期包与无服务端能力降级。
- 若变更来自服务端 core，应在源仓修复并经同步工具更新镜像，报告源版本及客户端兼容验证。
